Treat it as an active, very young reference implementation, not a stable CEDIA dependency.

## Verified design

- Search is a small, single-window macOS browser built with SwiftUI/AppKit and `WKWebView`; its package is one SwiftPM executable target for macOS 14+, with no reusable browser library or Electron/Code-OSS integration surface ([README](https://github.com/driceroland/Search/blob/cc8aa588bf6f212ea113bda0794edda0133bb139/README.md#L66-L90), [Package.swift](https://github.com/driceroland/Search/blob/cc8aa588bf6f212ea113bda0794edda0133bb139/Package.swift#L1-L11)).
- Its useful browser ideas are lazy tab web views, session restore, tab sleeping, per-site hidden selectors, content-rule ad blocking, reading mode, private data stores, and a compact tab/sidebar frame ([README](https://github.com/driceroland/Search/blob/cc8aa588bf6f212ea113bda0794edda0133bb139/README.md#L19-L31), [README](https://github.com/driceroland/Search/blob/cc8aa588bf6f212ea113bda0794edda0133bb139/README.md#L82-L90)). These are product patterns, not portable components for CEDIA's Chromium renderer.
- The optional `Bench` interface is a local Unix socket, mode `0600`, with same-UID peer checking, one JSON request per connection, size/time limits, and background “bench” tabs kept out of session/history ([Bench.swift](https://github.com/driceroland/Search/blob/cc8aa588bf6f212ea113bda0794edda0133bb139/Sources/Search/Bench.swift#L4-L14), [Bench.swift](https://github.com/driceroland/Search/blob/cc8aa588bf6f212ea113bda0794edda0133bb139/Sources/Search/Bench.swift#L61-L137), [Bench.swift](https://github.com/driceroland/Search/blob/cc8aa588bf6f212ea113bda0794edda0133bb139/Sources/Search/Bench.swift#L164-L226)).
- The socket is a testing/automation surface, not a safe agent API. `tabs` exposes every tab; `go`, `text`, `eval`, `click`, `type`, `sleep`, and `shot` find by arbitrary tab id without requiring `tab.bench`; only `close` enforces the bench-tab check ([Bench.swift](https://github.com/driceroland/Search/blob/cc8aa588bf6f212ea113bda0794edda0133bb139/Sources/Search/Bench.swift#L233-L330)). A same-UID process that learns a normal tab id can therefore inspect or mutate the user's page.
- Search can install Chrome Web Store CRX3 extensions after checking the extension id/signature, and adds WebKit compatibility shims; this is coupled to WebKit 15.4+ and extension storage, not to CEDIA's existing Chromium/OMP boundary ([Crx.swift](https://github.com/driceroland/Search/blob/cc8aa588bf6f212ea113bda0794edda0133bb139/Sources/Search/Crx.swift#L5-L17), [Crx.swift](https://github.com/driceroland/Search/blob/cc8aa588bf6f212ea113bda0794edda0133bb139/Sources/Search/Crx.swift#L73-L136), [README](https://github.com/driceroland/Search/blob/cc8aa588bf6f212ea113bda0794edda0133bb139/README.md#L84-L90)).
- The license is MIT, but the README asks a distributed fork to retain the license and rename the “Search” product/icon ([LICENSE](https://github.com/driceroland/Search/blob/cc8aa588bf6f212ea113bda0794edda0133bb139/LICENSE), [README](https://github.com/driceroland/Search/blob/cc8aa588bf6f212ea113bda0794edda0133bb139/README.md#L112-L114)).

## CEDIA decision

Do **not** embed or fork the whole app. It is a native WebKit browser executable, while CEDIA's agent window is Electron/Code-OSS Chromium and OMP must remain the sole execution/transcript owner. A fork would create a second browser engine, UI/runtime owner, update path, and security boundary.

Borrow only bounded ideas: (1) browser-pane tab/session state with lazy creation and explicit suspended/restored states, (2) per-site page cleanup/content rules only if CEDIA has a concrete need, and (3) a typed browser capability contract for OMP tests: opaque tab handles, allowlisted actions, bounded text/screenshot artifacts, cancellation/timeouts, and no arbitrary JavaScript by default. Keep this contract in CEDIA's host/protocol and apply the existing CEDIA device/auth policy; do not expose Search's same-UID bench socket to agents, remote clients, or production pages.

Search contributes nothing useful to the terminal surface. Keep terminal PTY ownership and user-shell semantics in CEDIA/Code-OSS; use Ghostty/Orca research separately if a terminal renderer or accessibility feature proves necessary. Revisit Search only as a read-only design reference after the browser capability slice has acceptance tests.
