# Synara v0.9.2 intake assessment — 2026-09-26

Status: research only. No vendor update, runtime upgrade, feature adoption, or acceptance gate is claimed. CEDIA-PLAN.md remains the only plan/spec. Recommendations below are intake candidates, not a second implementation backlog.

## Decision summary

Selective reuse is worthwhile. Prioritize transcript/scroll correctness and rendering efficiency, approval redaction, process/transport failure handling, and model-catalog startup behavior. Use upstream's new OMP adapter as a source of compatibility tests and selected presentation logic; do not replace CEDIA's host or RPC bridge simply because Synara now advertises OMP.

The release contains OMP support, but **Stable hides and disables it; Synara Beta enables it**. Its integration launches `omp acp`. CEDIA uses its existing OMP `rpc-ui` owner and pinned CEDIA operations. ACP integration is not evidence of full CEDIA O01–O12, Code-OSS, two-window, remote, or iPhone parity.

## Intake priority and acceptance constraints

Suggested order for the existing upstream-intake process, without changing the delivery baseline:

1. Approval redaction and transcript correctness, alongside focused regressions; retain the new panel-stack fix.
2. Small rendering/streaming/idle-efficiency improvements with measurable behavior preserved.
3. Transport, cancellation, restart settlement and cached-catalog behavior only where current CEDIA code has a demonstrated gap.
4. OMP roles/discovery/settings UX and a differential capability assessment before considering any adapter substitution.
5. O10 consent/preview/native interaction patterns and guarded worktree cleanup through existing owners.
6. Optional PR/import/visual polish after Mac/native acceptance, not as a moving prerequisite for the current delivery.

Acceptance before adoption: preserve single OMP execution/transcript/auth owner; no alternate harness registration; no credential duplication; explicit stale cache state; current provider/model validation at send; exactly-once approval/command effects; no mutation replay after uncertain outcomes; no dangerous worktree cleanup; no Keychain in own-use builds; no independent upstream self-update. Run relevant contract tests plus packaged two-window behavior on the actual integrated revision. Native auth and device requirements use existing authorization; no new paid service, telemetry endpoint, Chrome-profile extension, or signing/deployment grant follows from this research.

The remaining CEDIA F gates do not disappear when upstream gains ACP support. `switchSession` remains open under the owner's existing instruction, D1–D5 remain excluded at their precise agreed scope, and browser/remote/iPhone/lifecycle qualification continues under the main plan. This intake neither broadens nor settles those decisions.

## Detailed OMP and catalog compatibility review

Scope: read-only review of Synara source at a33435c18474eb7816582004e45f87382965ac8d (v0.9.2), plus official PR #1166 and #1332. Code facts refer to that revision; live/test evidence is PR-author claims, not independently reproduced. No upstream code was run.

### Assessment

Use Synara's OMP work as selective source material, not a blanket adapter replacement. It preserves OMP as child process, ACP session owner, model router, account, and local credential owner. But it replaces the host protocol with ACP; this does not preserve CEDIA's rpc-ui path or extensive cedia_control operations. Keep rpc-ui authoritative unless ACP proves parity on CEDIA's real operation inventory, pinned binary, and two-window behavior.

Candidates: model metadata/thinking options via omp models --json, layered modelRoles parsing, ACP lifecycle/cancellation regression cases, and persisted catalogs for slow non-OMP providers. ACP is a possible future transport, not a demonstrated drop-in replacement.

### Exact support and gaps

At this revision, OMP runs omp acp over stdio with Synara's shared ACP runtime. It supports session start/resume, turn streaming, model/thinking/mode config, native permission and elicitation requests, cancellation, conditional ACP fork, slash-command discovery, external JSONL session import, and rollback by retained transcript/restart. Native rewind is absent. Composer flags: slash discovery and runtime model list supported; skill/plugin mentions and discovery unsupported; thread compaction unsupported over ACP; thread import supported. OMP TUI /compact is not an ACP compaction method. [OmpAdapter capabilities](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/Layers/OmpAdapter.ts#L2137-L2152) · [adapter methods](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/Layers/OmpAdapter.ts#L2370-L2393) · [rollback fallback](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/Layers/OmpAdapter.ts#L1987-L2003).

ACP fs/terminal handlers are generic workspace plumbing, not proof of parity with rpc-ui or CEDIA control calls. [AcpSessionRuntime handlers](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/acp/AcpSessionRuntime.ts#L744-L772).

Cancellation closes the session/process tree after cancel because nested OMP workers may outlive an acknowledged cancel. The adapter also has an idle watchdog and special liveness treatment for Task tool rows; these are useful regression cases but need mapping to CEDIA process ownership. [Watchdog settings](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/Layers/OmpAdapter.ts#L149-L167) · [interrupt path](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/Layers/OmpAdapter.ts#L1867-L1930).

ACP session/request_permission returns host approval responses. PR #1166 reports live approval for bash but documents an upstream gap: OMP protects bash/edit/delete/move; write and third-party MCP tools can run without permission requests. Synara reports a separate host gate for its device/computer tools. ACP permission cards alone do not prove all CEDIA mutators are gated. Require deny/no-side-effect tests for write and every exposed MCP mutator. [PR #1166 known gaps and verification](https://github.com/Emanuele-web04/synara/pull/1166).

### Auth and profile ownership

The adapter launches configured OMP binary as omp acp and sets PI_CODING_AGENT_DIR if configured. OMP owns profile auth/sessions/models. ACP init selects only the advertised agent auth method and passes headless:true; if unavailable, the error instructs the user to authenticate by running omp. Credentials therefore remain in OMP's profile rather than duplicated in Synara. [Spawn/profile](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/acp/OmpAcpSupport.ts#L101-L117) · [auth resolution](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/acp/OmpAcpSupport.ts#L120-L157).

CEDIA pins OMP 18.1.18; #1166's author-reported live run used 18.2.8. That does not prove the earlier pin has the same ACP auth method, config options, model JSON shape, fork, or permission behavior. Check each against 18.1.18 before adoption.

### Models, roles, and cache

Model discovery invokes omp models --json and normalizes selector, name, provider, and thinking levels. Model and effort are set through ACP session config (model first); plan mode sets advertised mode=plan or leaves current mode. [CLI discovery](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/Layers/OmpAdapter.ts#L438-L492) · [normalization](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/acp/OmpAcpSupport.ts#L555-L609) · [config options](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/acp/OmpAcpSupport.ts#L159-L228).

Roles load from global and project OMP YAML, with project overriding same-named global roles. Parser supports ordered fallback chains, @role/pi/role/* aliases and cycle dropping, provider-locked matching, and thinking suffixes. It rereads role files per request. Limits acknowledged by PR author: it does not read OMP built-in priorities from priority.json; fuzzy matching approximates OMP's usage-sensitive scorer and tie behavior. [Role grammar](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/acp/OmpAcpSupport.ts#L279-L440) · [role parsing](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/acp/OmpAcpSupport.ts#L441-L552) · [config layering](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/Layers/OmpAdapter.ts#L2230-L2279).

PR #1332 is merged. Its author reports atomic stateDir snapshots, corruption tolerance, coalesced writes, cache freshness/stale windows, and focused tests, but explicitly says live provider/account testing and end-to-end benchmarking were not performed. [PR #1332](https://github.com/Emanuele-web04/synara/pull/1332). OMP deliberately bypasses this shared durable cache so project role edits remain fresh. It has its own in-memory model-list cache for 5 minutes keyed by binary path and agentDir; role files are reread each request. Thus #1332 does not currently remove OMP's post-restart catalog discovery wait. [OMP bypass](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/Layers/ProviderDiscoveryService.ts#L371-L384) · [adapter cache and roles](https://github.com/Emanuele-web04/synara/blob/a33435c18474eb7816582004e45f87382965ac8d/apps/server/src/provider/Layers/OmpAdapter.ts#L2154-L2279).

For CEDIA, cached models should be last-known display data with explicit refresh/invalidation. Test restart warmup, corrupt snapshots, account/profile changes at same path, binary/agentDir changes, empty discovery, and live project-role edits. Don't persist role results under a key that hides cwd config changes.

### Acceptance checks for selective adoption

1. On OMP 18.1.18, capture actual model JSON, auth initialization, ACP config options, permission requests, fork support, and command discovery; verify parser and settings against that evidence.
2. Test role overrides, aliases/cycles, fallback order, provider selectors, thinking suffixes, and selected outcomes against OMP; surface unresolved roles.
3. Compare rpc-ui and ACP across CEDIA's cedia_control inventory and two-window routing, all mutators, streaming/mode/effort, attachments, nested agents, import/resume/fork/rollback/compaction, terminal/fs, and cancel. Require denied write/MCP mutators to have no side effects.
4. Test cache restart, corrupt-file recovery, refresh, account/profile changes at same path, binary/agentDir changes, empty discovery, and live project role changes.

## CEDIA source boundaries checked during intake

These are present implementation seams, not fresh runtime acceptance claims.

- `packages/omp-adapter/src/client.ts`: `OmpRpcClient` owns `--mode rpc-ui`, explicit environment isolation, ready/negotiation and request/event handling. `framing.ts` owns NDJSON and v2 chunk decoding (separate physical/logical limits). Do not replace these with ACP frame handling without preserving the negotiated protocol.
- `apps/host/src/provider-auth.ts` and `omp-settings.ts`: native OMP metadata/auth operations, credential filtering, settings revision/CAS and protected-key handling. OMP profile absence in an isolated fixture does not prove the personal OMP login is absent.
- `packages/omp-adapter/src/ui.ts` and `apps/macos/src/approval-runtime.ts`: request identity, cancellation/expiry and one-winner responses already exist. Compare the redaction/permission additions against these paths rather than create parallel approval state.
- `apps/host/src/store.ts` and `service.ts`: durable turn intent, recovery and unknown-outcome handling already exist. Recovery must not translate unknown outcomes into success or auto-replay mutations.
- `apps/host/src/model-catalog.ts`: current process-local 30-second cache, single-flight discovery and invalidate path; `apps/macos/src/omp-catalog.ts` projects session-backed catalog state. A durable last-known cache would be new work, with explicit stale/readiness treatment.
- `apps/host/src/service.ts`, `workspaces.ts` and `git.ts`: cleanup/restore protocol and conservative worktree checks exist; cleanup remains disabled unless its enabling gates pass. Source machinery alone is not a deletion authorization.
- `apps/macos/src/agent-window-browser.ts` and `cdp-tab-endpoint.ts`: task-scoped attachment and browser bridge work is active. Its in-progress packaged proof belongs to the implementation thread; this research neither edits nor certifies it.
